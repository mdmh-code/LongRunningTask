🚀 Long Running Task

Distributed Microservices Architecture for Asynchronous Message Processing

📋 Executive Summary

Project Overview

Long Running Task is a distributed, event-driven microservices application designed to process string messages asynchronously with real-time progress tracking. The system demonstrates modern cloud-native architecture patterns including message queuing, background processing, real-time communication, and containerized deployment.

🎯 Key Features

  • Asynchronous Processing: Non-blocking message processing using RabbitMQ message broker
  • Real-time Updates: SignalR WebSocket communication for live progress tracking
  • Responsive UI: Modern React-based web interface with Bootstrap styling
  • Scalable Architecture: Microservices pattern with independent service scaling
  • Progress Tracking: Visual progress bar showing character-by-character processing
  • Cancellation Support: Users can cancel long-running operations
  • Persistence: PostgreSQL database for job status tracking
  • Authentication: Nginx-based authentication gateway

▶️ How to Run

Prerequisites
  • Docker Desktop installed and running
  • Docker Compose (included with Docker Desktop)
  • At least 4GB of available RAM
  • Ports 5173, 8080, 9090, 5672, 15672, and 5432 available

🚀 Quick Start

# Clone the repository git clone <repository-url> cd LongRunningTask # Build and start all services docker-compose up --build # Access the application # Open browser at: http://localhost:5173
⚠️ Note: The first build may take several minutes as Docker downloads base images and builds all services.

🛑 Stopping the Application

# Stop all services docker-compose down # Stop and remove volumes (clean state) docker-compose down -v

🏛️ Architectural Layers

1. Presentation Layer
  • LongRunningTask.WebApp: React SPA with real-time UI updates
  • Authentication Gateway: Nginx reverse proxy with basic authentication
2. API Layer
  • LongRunningTask.API: REST endpoints for message submission
  • SignalR Hub: Real-time WebSocket communication
  • Message Publishing: Event publishing to RabbitMQ
3. Domain Layer
  • LongRunningTask.Domain: Core business logic
  • StringProcessor: Message processing algorithms
  • Interfaces: Dependency abstractions
4. Infrastructure Layer
  • LongRunningTask.Infrastructure: Technical implementations
  • Message Consumers: RabbitMQ event handlers
  • Repository Pattern: Database access abstraction
5. Processing Layer
  • LongRunningTask.Processor: Background worker service
  • Job Management: Status tracking and persistence

💡 Key Architectural Concepts

🎭 Event-Driven Architecture

The system uses an event-driven approach where services communicate through asynchronous messages. This decouples components, allowing them to scale independently and fail gracefully.

📦 Microservices Pattern

Each service has a single responsibility: API handles requests, Processor executes jobs, and Web provides the interface. Services communicate only through well-defined contracts.

🔄 CQRS-Inspired Design

Request handling (API) is separated from processing (Processor). Commands flow through RabbitMQ, and responses return via SignalR, creating a clear separation of concerns.

⚡ Real-Time Communication

SignalR enables server-to-client push notifications, providing instant feedback as each character is processed without polling.

🐳 Container Orchestration

Docker Compose manages multi-container deployment with health checks, dependency ordering, and network isolation, ensuring reliable startup and runtime.

💾 Persistence Layer

PostgreSQL stores job status and history, enabling recovery from failures and providing audit trails. Entity Framework Core manages data access with migrations.

🧪 Testing the Application

Basic Workflow Test
  1. Open http://localhost:5173 in your browser
  2. Enter a message (e.g., "Hello World") in the input field
  3. Click the Send button
  4. Observe the progress bar animating as characters are processed
  5. Watch the processed text appear character by character
  6. See the completion message when processing finishes
Cancellation Test
  1. Enter a long message (e.g., 100+ characters)
  2. Click Send to start processing
  3. While the progress bar is animating, click Cancel
  4. Verify that processing stops and the progress bar resets
Monitor Services
  • RabbitMQ Management: Visit http://localhost:15672 (guest/guest) to see message queues
  • Docker Logs: Run docker-compose logs -f [service-name] to see real-time logs
  • Database: Connect to PostgreSQL at localhost:5432 to inspect job records
